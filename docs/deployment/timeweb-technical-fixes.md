# Технические исправления: Timeweb

Статус на 27.10.2026: подготовлено локально, не опубликовано. Связанные находки аудита: F05–F10, F19.

## Что делает production-сборка

`python3 scripts/package-site.py --output /новая/папка --production`

- Сохраняет DirectoryIndex и три существующих защитных заголовка Apache.
- Перенаправляет www на https://smirnovads.com с сохранением пути и query.
- Исключает существующий ACME challenge из всех собственных редиректов.
- Перенаправляет явные index.html и корневой index.htm на каноничный URL каталога.
- Добавляет завершающий слеш существующим каталогам сразу через HTTPS, до mod_dir.
- Использует /404.html как ErrorDocument с исходным статусом 404.
- Добавляет к локальным CSS/JS/mjs в HTML параметр v из SHA-256 экспортируемых байтов. Исходные HTML и сторонние URL не перезаписывает. Повторная сборка одинаковых файлов стабильна; при изменении ресурса его URL меняется. Версии нужны именно из экспортированной сборки: копирование исходных HTML напрямую их не добавляет.

Preview-режим сохраняет прежние noindex и отключение счётчика; production-редиректы в него не добавляются. Публикация отдельного клиентского preview не менялась.

## Что требует nginx на Timeweb

Файл `_headers` не управляет nginx Timeweb. Apache `.htaccess` также не задаёт заголовки ресурсов, которые nginx отдаёт напрямую. Поэтому F06 нельзя считать закрытой по результату локальной сборки.

При следующей согласованной публикации проверить в панели/через поддержку Timeweb настройки именно основных smirnovads.com и www. Требуемое состояние HTML, CSS, JS/mjs, SVG, изображений, favicon, robots и ошибок 403/404:

```nginx
add_header X-Content-Type-Options "nosniff" always;
add_header X-Frame-Options "DENY" always;
add_header Referrer-Policy "strict-origin-when-cross-origin" always;
```

Это целевые директивы для существующих server/location, а не полный конфиг для замены. Нужно учесть наследование add_header: наличие директив на вложенном уровне обычно отменяет наследование с верхнего. Не удалять другие заголовки и не создавать дубли X-Frame-Options при проксировании Apache. Попросить поддержку проверить конфигурацию и reload; не ослаблять защиту глобально ради карт Метрики.

CSS/JS после production-сборки имеют версии в URL. Долгий кэш допустим, если nginx учитывает query в cache key. Это нужно проверить после загрузки. Для неверсионированных изменяемых изображений/файлов — отдельно сократить срок или версионировать при изменении. Кэш HTML не должен удерживать старые ссылки на версии ресурсов. Старые файлы и служебные файлы без отдельной команды не удалять.

## Публикация и приёмка

Публикация разрешается только командой владельца «публикуй»/«деплой». До неё никаких изменений Timeweb/DNS.

1. Следовать AGENTS.md: проверить remote и рабочую папку, не включать черновики и отчёты в публичную сборку; зафиксировать SHA согласованных изменений.
2. Собрать production из этого SHA. Сверить текущие управляемые файлы сервера с предыдущей опубликованной сборкой, сохранить backup, отдельно сравнить .htaccess. Не перезаписывать неожиданные серверные изменения.
3. Загрузить эту же сборку с Mac. Учесть, что HTML сборки теперь отличается от исходного HTML версиями CSS/JS; сверять SHA-256 с экспортом, а не с сырым исходником.
4. Проверить без автоматического следования редиректам:
   - /blog?utm_source=test → 301 на https://smirnovads.com/blog/?utm_source=test;
   - HTTPS www с вложенным путём и параметрами → основной HTTPS с теми же данными;
   - /blog/index.html?next=/other/index.html → /blog/ с неизменным query;
   - /index.htm → главная, без удаления серверного файла;
   - /blog/ → 200 без цикла внутреннего index.html;
   - неизвестный вложенный URL → собственный HTML и статус 404;
   - существующий challenge-файл доступен для обоих имён; проверка выдуманного файла с 404 не доказывает продление;
   - CSS/JS/изображения и 403/404 получают нужные заголовки; нет дублей и случайного noindex на основном сайте.
5. Сверить все пути/SHA-256 с production-экспортом. Проверить robots/sitemap, сертификаты, загрузку Метрики, её ID и контактные действия; первый визит после прогретого кэша получает актуальные CSS/JS.

Проверки локально: `node tests/utm-utils.test.mjs`, `node tests/utm-page.test.mjs`, `python3 tests/site-package.test.py`, `python3 tests/server-routing.test.py`. Последняя команда запускает одноразовый Apache на localhost и доступна на Mac с системными модулями Apache; на других платформах тест явно пропускается. Это не полная эмуляция nginx → Apache Timeweb, поэтому внешняя приёмка обязательна.

Первичные источники: [ErrorDocument](https://httpd.apache.org/docs/2.4/mod/core.html#errordocument), [RewriteRule flags](https://httpd.apache.org/docs/2.4/rewrite/flags.html), [nginx headers](https://nginx.org/en/docs/http/ngx_http_headers_module.html).
